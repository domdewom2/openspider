## 2a Ausführungsregeln Cloud (Orchestrator und Pakete)

Lehren aus M1 (E1–E8) sind übernommen: E4 → C7, E5 → C8, E6/E8 → Nacharbeitspakete N0x je Welle, E7 → C9, Welle-6-Besitzregel K-65 → C10, „abhängige Pakete nie in dieselbe Welle“ → C1 (und per Skript geprüft), Startprüfung per `git log … --grep='Merge …'` → C1, Messungen nur auf ruhiger Maschine → C11.

- **C1 Start eines Pakets:** Der Orchestrator startet eine Cloud-Session mit dem Branch `m2/<kurz-id>` von `origin/main`, sobald **alle** `depends_on` gemergt sind: je Abhängigkeit `git log --oneline origin/main -i --grep='Merge <kurz-id>'` mit genau einem Treffer (Merge-Commits heißen `m2: Merge <kurz-id>`). Eine Welle besteht nur aus Paketen ohne Abhängigkeiten untereinander; innerhalb einer Welle startet jedes Paket, sobald seine eigenen Voraussetzungen erfüllt sind (in Welle 1 starten Kern- und Fachpakete nach M2-F02/F03, UI-Pakete nach M2-G0). **N-Pakete** (N01, N02) starten erst, wenn **alle** Pakete ihrer Quellwelle gemergt sind (N01: alle 45 Welle-1-Pakete; N02: alle übrigen Welle-2-Pakete); `depends_on` führt sie vollständig auf, damit jeder Platzhalter-Ort aus C9 beim Start existiert (Prüfskript P11). Session-Auftrag = `prompt_notes` + Verweis auf die genannten Abschnitte dieses Plans.
- **C2 Keine lokalen Pfade:** In Code, Tests, Skripten und Prompts nur Pfade relativ zur Repo-Wurzel; temporäre Daten über `tempfile`; App-/Nutzerordner über `dirs` bzw. `OPENSPIDER_HOME`. Ports ephemer, außer den festen Paritätsports (die Session ist isoliert, kein `lockf` nötig).
- **C3 Umgebung:** `scripts/cloud/setup.sh` (M2-F01) richtet ein: Rust laut `rust-toolchain.toml`, Node 22 (`engines`), `npm ci`, `npx playwright install --with-deps chromium webkit`, `OPENSPIDER_CHROMIUM` = Chromium aus Playwright, optional `libwebkit2gtk-4.1-dev librsvg2-dev libayatana-appindicator3-dev` für `openspider-desktop` unter Linux, `OPENSPIDER_SECRET_STORE=memory` (C13; **kein** Secret Service/gnome-keyring). Das Skript ist idempotent und läuft in jeder frischen Cloud-Session sowie im eigenen Linux-Job `.github/workflows/cloud-setup.yml` (Besitz M2-F01).
- **C4 Bauen und Testen in der Cloud:**
  - Rust: `cargo fmt --all --check && cargo clippy --workspace --exclude openspider-desktop --all-targets --locked -- -D warnings && cargo test --workspace --exclude openspider-desktop --locked`
  - Desktop-Hülle (nur Pakete mit `apps/desktop/src-tauri/**` in `owns`): zusätzlich `cargo clippy -p openspider-desktop --locked -- -D warnings`, wenn webkit2gtk installiert ist; sonst Nachweis über die CI-Matrix.
  - Frontend: `npm run -w apps/desktop typecheck && npm run -w apps/desktop test && npm run -w apps/desktop check:static`
  - E2E-A: `npm run -w apps/desktop e2e -- --project=chromium --project=webkit` (startet `os-app-bridge` mit Fixture-Daten).
  - macOS/Windows-spezifische Prüfungen (WKWebView, WebView2, Tauri-Build, E2E-B) laufen über den Push des Branches in der CI-Matrix; der Paketbericht nennt die Lauf-ID.
- **C5 Ressourcen:** `CARGO_INCREMENTAL=0`, `CARGO_PROFILE_DEV_DEBUG=line-tables-only`, `CARGO_PROFILE_TEST_DEBUG=line-tables-only`; große Testdaten nur in Benchmark-Ignores; keine Binärdateien > 1 MB im Repo außer gebündelten Ressourcen (axe-core, Wörterbücher, Vokabulardateien) mit Lizenzvermerk.
- **C6 Abschluss:** Draft-PR „M2-xx: <Titel>“ mit Bericht; der Orchestrator merged nach grüner CI mit `git merge --no-ff -m 'm2: Merge <kurz-id>'`, pusht `main`, löscht den Branch. N-Pakete einer Welle werden vor den übrigen Paketen derselben Welle gemergt.
- **C7 Manifeste:** `Cargo.toml`, `Cargo.lock`, `crates/*/Cargo.toml`, `package.json`, `package-lock.json` ändern nur M2-F01 (Rust; ohne die Manifeste von `os-store`, `os-engine`, `os-analyze`, C14), M2-F02 (nur diese drei Manifeste und deren `Cargo.lock`-Einträge, Welle 0b) bzw. ### 3.7 Tauri-Hülle (M2-F03)

- Je Command-Domäne ein internes Plugin `plugin:<domäne>|<command>` (M2-ui-concept 4.1), **mechanisch erzeugt** aus `commands.json` über ein Makro, das an `App::dispatch` weiterleitet; `lib.rs` registriert die Liste und ist danach eingefroren. Neue Commands späterer Pakete brauchen nur den Registry-Eintrag in `os-app` und die erneute Erzeugung durch das N-Paket der Runde.
- `events.subscribe(channel)` je Fenster (Tauri `Channel<UiEvent>` → `EventSink`), Fensterereignisse (`Focused`, Minimiert, macOS-Occlusion) → `App::set_visibility`.
- Schließen/Beenden (F-11): `CloseRequested`, `RunEvent::ExitRequested` → `App::request_quit`; Rückfrage im Frontend.
- Plugins: dialog, clipboard-manager (Rust-Seite schreibt, `view.copy`), notification, os (Locale), single-instance (OUT-232: Pfad an laufende Instanz → `crawl.open`), deep-link/Dateizuordnung `.ospider` (OUT-272); `tauri-plugin-wdio-webdriver` nur mit Feature `e2e-webdriver`.
- URI-Schema `ospider://shot/<crawl>/<urlId>/<tile>` und `ospider://img/…` → `os_app::assets::resolve` (Implementierung M2-K09).
- `tauri.conf.json`: Fenster `main` (min 1 024 × 640), `settings`, `viz-*` (dynamisch), `bundle.macOS.minimumSystemVersion = "13.0"`, CSP ohne externe Quellen, `fileAssociations` für `.ospider`.
