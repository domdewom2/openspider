## 2 Arbeitsregeln für alle Pakete

1. **Clean-Room:** nur `docs/spec/*` und dieser Plan. Kein Blick in Screaming Frog. SF-Exporte unter `tests/golden/parity/*/sf/` sind Messdaten, die der Nutzer manuell erzeugt; Agents lesen sie nur über `os-parity`, kopieren keine Texte daraus (Beschreibungsspalten werden beim Einlesen verworfen).
2. **Worktree & Branch:** je Paket ein Worktree, Branch `m1/pxx-<slug>` (z. B. `m1/p02-fetch-http`), Commits klein mit Bereichspräfix (`fetch:`, `parse:` …).
3. **Dateibesitz:** Ein Paket ändert nur Dateien aus seiner Spalte `owns` (Globs). Alles andere ist innerhalb der Welle tabu. Insbesondere:
   - Root-`Cargo.toml`, alle `crates/*/Cargo.toml` und alle `crates/*/src/lib.rs` gehören **Schritt 0** (M1-P00). Später nur, wenn das Paket in seiner Welle alleiniger Besitzer der Crate ist (steht dann in `owns`).
   - Fehlt eine Abhängigkeit oder ein Typ in `os-model`: nicht selbst ändern, sondern im Ergebnis unter „Schnittstellenbedarf“ melden; der Orchestrator bündelt Änderungen zwischen den Wellen.
   - `Cargo.lock`-Konflikte beim Mergen löst der Orchestrator durch `cargo check` (Lock wird neu erzeugt).
4. **Stubs aus Schritt 0** tragen den Kommentar `// STUB(M1-Pxx)`; das genannte Paket ersetzt sie. Kein `todo!()`/`unimplemented!()` im Code, der von Tests anderer Pakete erreicht werden kann; Stubs liefern leere Ergebnisse bzw. `Err(NotImplemented)`.
5. **Spec-Referenz im Test:** direkt über jeder Testfunktion `// spec: CRAWL-014` (mehrere: `// spec: CRAWL-014, CRAWL-017`). Jede M1-ID des Pakets braucht ≥ 1 grünen Test gegen eine Fixture (Unit-Tests zusätzlich erlaubt). Zurückgestellte Kriterien: `#[ignore = "M2: <ID> <Grund>"]` bzw. `#[ignore = "Klärung K-xx"]`, darüber `// spec: <ID> [M2]`.
6. **Golden-Dateien:** Filter-Adresslisten (`tests/golden/<szenario>/<tab>__<filter>.csv`) und konkrete Werte aus Akzeptanzkriterien werden **aus der Spec abgeleitet** und als explizite Assertions geprüft. Breite Regressions-Goldens (ganze Exporte) dürfen mit `UPDATE_GOLDEN=1` aus der eigenen Ausgabe erzeugt werden, aber erst wenn die spec-abgeleiteten Tests grün sind; jede Golden-Änderung im Commit begründen.
7. **Definition of Done (für jedes Paket zusätzlich zur Paket-DoD):** `cargo fmt --all --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace` grün; `cargo deny check licenses bans sources` grün; keine neuen Warnungen; plattformneutral (keine Pfadtrenner, `dirs`, kein Shell-Aufruf); Tests laufen ohne Netz (nur `os-testsite` auf Loopback); Ergebnisbericht mit: umgesetzte IDs, zurückgestellte Kriterien mit Grund, Spec-Unklarheiten, Schnittstellenbedarf.
8. **Determinismus:** Zeit nur über `os_model::time::Clock`, Crawl-IDs nur über `IdSource`. Keine Zufallszahlen ohne Seed.
9. **Fixtures:** werden von `os-testsite` ausgeliefert; Manifest ist `scenario.toml` (siehe K-05). Verzeichnisnamen wie in der jeweiligen Spec: `tests/fixtures/crawl-*` (01), `onpage-*` (02), `tech/<slug>` (03), `out-*` (06), `agent-*` (10), `parity-*` (Abschnitt 5).

### 3.7 Datenfluss je URL (verbindlich für P15/P19)

1. Frontier (BFS, Priorität 0 = über Links, 1 = nur über Sitemap; innerhalb Tiefe aufsteigend, dann `seq`) liefert `(UrlId, Url, depth, cookie_session)`.
2. `RobotsGate::check` (bei Erstabruf je Origin wird die robots.txt selbst als URL-Zeile gespeichert, zählt nicht für Limits/Fortschritt).
3. `Fetch::fetch` (Rate-Limit liegt im Fetcher und gilt für alle Abrufe inkl. robots.txt).
4. Bei HTML intern: `os_parse::parse_html` + `parse_headers`; Nicht-HTML: nur `parse_headers`; CSS: `parse_css`; Sitemap: `parse_sitemap`; PDF: `parse_pdf_meta`.
5. Engine normalisiert alle Ziele (`os-url`), klassifiziert intern/extern, wendet Speichern/Crawlen-Matrix, Nofollow, Include/Exclude, Tiefe/Limit an, vergibt `UrlId` für neue URLs (In-Memory-Seen-Set aus 64-Bit-Hashes, SQLite-UNIQUE als Wahrheit), bildet `PageWrite` inkl. `indexability::evaluate`.
6. `WriteBatch` → begrenzter Kanal → Writer-Thread (`SqliteSink`) → Transaktion (max. 200 Seiten oder 100 ms). Volle Kanäle drosseln die Worker (PERF-003).
7. Fortschritt über `watch`-Kanal; Heartbeat alle 2 s in `crawl_meta`.

### 5.3 Ablauf

1. P10 legt Sites, Manifeste (`status = "pending"`), Mappings und `README.md` an.
2. **Nutzer** startet je Site `os-testsite <site> <port>`, crawlt `http://127.0.0.1:<port>/` mit SF Free (Standardkonfiguration), exportiert die Liste aus dem Manifest nach `sf/`, setzt `status = "present"` bzw. `unavailable`. Kein Agent bedient SF.
3. P29 führt `os-parity run --all` aus: Site starten, `openspider --crawl … --config tests/parity/profiles/parity.osconfig --export-tabs … --bulk-export … --save-report …`, beide Seiten normalisieren, vergleichen.
4. Jede Abweichung ist entweder ein Bug (→ Nachbesserungspaket) oder steht in `deviations.toml` mit Spec-ID und Kennzeichen (Paritätsabweichung/Annahme/OS-Festlegung).

### 5.4 Runner `os-parity` (P11)

```
os-parity diff --sf <csv> --os <csv> --mapping <toml> --sf-base <url> --os-base <url> [--out <dir>]
os-parity run --site <name>|--all [--openspider <pfad>] [--out target/parity]
os-parity coverage --packages docs/plan/M1-packages.json [--write docs/plan/M1-status.json]
```
Bericht `target/parity/report.json` + `report.md` je Export: `sf_rows`, `os_rows`, `matched`, `missing_in_os[]`, `extra_in_os[]`, `cells_compared`, `cells_equal`, `agreement_pct`, je Spalte Fehlzahl + bis zu 10 Beispiele, Liste angewandter Abweichungen. Exit-Code 0 nur, wenn alle Schwellen aus 6 (A3) erfüllt sind. CSV-Einlesen tolerant gegenüber BOM, CRLF/LF, Komma/Semikolon (Autodetektion), Anführungszeichen.

## 9 Risiken und Gegenmaßnahmen

- **Engine als Engpass (P15/P19):** größte Pakete auf dem kritischen Pfad. Gegenmaßnahme: Datenfluss und Typen sind in Schritt 0 fest; P15 darf nichts an `os-model` ändern, sondern nur melden.
- **Testsite-Fähigkeiten fehlen früh (P09 parallel zu P02/P03):** Tests mit `#[ignore = "wartet auf M1-P09"]` erlaubt, P15 schaltet sie nach dem Merge scharf (steht in P15-DoD).
- **SF-Exporte nicht rechtzeitig:** A3 verlangt 4 von 5 Sites; P29 kann ohne SF-Daten den Rest der Abnahme vorbereiten.
- **Plattformunterschiede (RSS-Messung, Signale, Pfade):** P26/P28 testen auf allen drei CI-Runnern; Windows-SIGINT über `CTRL_C_EVENT`.
- **Lizenzen (rustls-Provider, rmcp):** P00 prüft mit `cargo deny` vor allem anderen.
