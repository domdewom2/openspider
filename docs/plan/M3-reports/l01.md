## Quellen und dokumentierte Sonderfälle

`rust-sources.json` enthält versionsgebundene Upstream-Lizenzdateien aus den über
`.cargo_vcs_info.json` belegten Commits; alle werden mit SHA-256 geprüft. Vier npm-
Archive enthalten keine Lizenzdatei: Fluent bundle/langneg, client-only und
react-easy-swipe. `npm-sources.json` dokumentiert feste Quellen, Hashes und Gründe.

Für fünf Rust-Pakete fehlen Texte auch upstream bzw. das Repository ist nicht mehr
verfügbar: genawaiter 0.99.1, genawaiter-macro 0.99.1, genawaiter-proc-macro 0.99.1,
next-gen-proc_macros 0.1.1 und selectors 0.38.0. `rust-canonical.json` erlaubt genau
für diese Versionen und exakten Lizenzdeklarationen die vollständigen kanonischen
cargo-about/SPDX-Texte, ergänzt um Cargo-Autoren, Repository und ausdrückliche
Herkunftsangabe. Andere fehlende Texte scheitern; es gibt keinen pauschalen Rückfall.
Details und Wartung: [Drittlizenzen](../../release/lizenzen.md).

Der Versuch, auch den gesamten Linux-Desktop-Graphen einzubeziehen, wurde verworfen:
Das Produkt liefert unter Linux ausschließlich die CLI. GTK-Build-Abhängigkeiten
enthielten tiny-keccak/CC0 außerhalb der vorhandenen Positivliste. Der separate
Linux-CLI-Graph enthält diese Komponente nicht; die Positivliste wurde nicht erweitert.

## Vom Orchestrator nach dem Push zu starten

Auf dem geprüften Integrationsstand mit diesen Commits, hier als Branch `m3/l01`:

```sh
gh workflow run licenses.yml --ref m3/l01
gh workflow run ci.yml --ref m3/l01 -f intel=true
gh workflow run release-macos.yml --ref m3/l01 -f arch=all -f channel=beta -f run_tests=true
gh workflow run release-windows.yml --ref m3/l01 -f channel=beta -f offline_webview=false
```

`version` beim macOS-Lauf leer lassen, solange der Workspace noch 0.1.0 ist; für einen
vorbereiteten Beta-Stand exakt dessen Workspace-Version verwenden. Bei fehlender
Registrierung eines neuen Dispatch-Workflows im Standardzweig den Integrations-/PR-Lauf
verwenden bzw. nach Integration dispatchen; keinen temporären Veröffentlichungsworkflow
anlegen. Lauf-IDs sind mangels Push **vom Orchestrator nachzutragen**.

Erwartung: `licenses.yml` erzeugt ein vollständiges `third-party-notices`-Artefakt;
CI prüft native Plattformen einschließlich Intel. Release-Workflows produzieren nur
Actions-Artefakte. Fehlende Signiersecrets dürfen wie bisher grün mit Hinweis
„unsigniert“/Skip enden. Ein macOS-Skip belegt keinen echten Installer: nach vorhandener
Apple-Konfiguration denselben Lauf wiederholen. Es wird kein GitHub-Release veröffentlicht.

M3-R04 übernimmt die Lizenzprüfung als Gate und NOTICE + THIRD_PARTY_NOTICES.txt auch
in das separate Linux-CLI-Archiv (Artefaktschnittstelle vorhanden). L01 ändert keine
Datei aus R04/U02; Beta-Manifeste und Veröffentlichungsentscheidungen bleiben dort.
