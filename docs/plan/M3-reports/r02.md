# M3-R02 – Windows-Installer und Signatur

Stand: 30.10.2026. Branch `m3/r02`, Basis `origin/m3/f01` (F01-Abschluss
`9b7c2e7c`). Ausführung: Linux-Build-Server. Kein Push, keine Veröffentlichung.

## Ergebnis

- Tauri-Overlay: NSIS pro Nutzer und MSI pro Rechner, eingebettete CLI, WebView2-Prüfung
  mit stillem Bootstrapper; Offline-Runtime per Build-Eingabe optional.
  VC-Runtime für CLI und Desktop statisch eingebunden.
- NSIS: Benutzer-PATH, Startmenü, Dateizuordnungen aus der gemeinsamen Konfiguration.
  MSI: Rechner-PATH optional über `ADDTOPATH=1`, CLI immer installiert, fester Upgrade-Code.
- Installer rufen `openspider --uninstall-cleanup` auf. Die CLI entfernt ausschließlich
  OS-Aufgaben aus `\OpenSpider\`, unabhängig von vorhandenen XML-Dateien, und reicht
  Fehler zurück. Update-Deinstallationen erhalten die Registrierungen.
- Daten bleiben standardmäßig erhalten. Interaktive Auswahl und `REMOVEUSERDATA=1`
  entfernen die Standarddatenordner des ausführenden Nutzers. Externe Crawls,
  `OPENSPIDER_HOME` und fremde Profile bleiben erhalten (siehe Anleitung).
- Azure Artifact Signing über GitHub-OIDC → Azure-CLI → SignTool/x64-Dlib,
  SHA-256 und RFC-3161-Zeitstempel. Tauri signiert Binärdateien, NSIS-Uninstaller und
  beide Installer; CLI zusätzlich vor dem Bundeln. Verifikation aller EXE/DLL/MSI
  in Bundle und signierter Installation verlangt `Valid` und einen Zeitstempel.
- Fehlen Azure-Werte, wird mit Hinweis **unsigniert** gebaut. Fehlen privater oder
  öffentlicher Updater-Schlüssel, werden Updater-Artefakte mit Hinweis übersprungen.
  Vollständig konfigurierte, aber fehlerhafte Signierung schlägt fehl.
- Beide Installer erhalten bei vorhandenen Updater-Schlüsseln eine `.sig`.
  Endpunktwahl über `channel` und `OPENSPIDER_UPDATE_BETA`, Beta: `latest-beta.json`.
- Workflow mit `workflow_dispatch` und `workflow_call` für R04, Artefakt
  `openspider-windows-x86_64`. Kein Chromium im Bundle.
- Windows-Tests für CSV-Export sowie Anlegen, Speichern unter und Wiederöffnen einer
  Crawl-Datei unter einem Pfad >260 Zeichen. SQLite-Verbindungen verwenden unter
  Windows normalisierte Pfade und `win32-longpath`, auch für Hintergrundverbindungen.

## Entscheidung K3-07

MSI ignoriert die vierte Versionsstelle beim Vergleich. Deshalb dreistellige Abbildung:
`major.minor.(patch*1000+stage)`, Beta `stage=N`, RC `stage=499+N`,
stabil `stage=999`. N: 1…499, Patch: 0…64, Major/Minor: 0…255.
Beta.1 → RC.1 → stabil → nächster Patch ist streng monoton.
Nicht unterstützte Werte brechen den Build ab. SemVer in App/Updater/NSIS bleibt erhalten.
Fixtures prüfen Reihenfolge, Grenzen, Beta-URL und deaktivierte Updater-Artefakte.
