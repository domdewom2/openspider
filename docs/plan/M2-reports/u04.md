## Befunde und Nachweise

1. **Native Dateidialoge (CRAWL-127, UI-002):** `chooseFile` ruft in Tauri
   `dialog.open` bzw. `dialog.save` über den vorhandenen Client auf. Öffnen und
   Import filtern auf `*.ospider`; Speichern unter und Crawl-Dateiexport bieten
   einen `.ospider`-Speicherort, MCP-Markdown einen `.md`-Speicherort. Auch der
   Diagnoseexport nutzt nach bestätigter Vorschau einen nativen ZIP-Dialog.
   Nur Browser/Bridge/Mock behalten die zugängliche Pfadeingabe. Abbruch löst keinen
   Fachcommand aus; Pluginfehler werden angezeigt; ein nach Fensterende
   bestätigter Dialog startet keine Arbeit. Tests: `help.test.tsx` gegen
   `fx-ui-basic`/MockCore mit Tauri-Transportkennung, Filter-/Argumentprüfung,
   Abbruch, Fehler und Fensterende. Bestehende Browser-Fallbacktests bleiben grün.
   Verzeichnisdialoge für Bulk/Reports/Sitemaps gehören nach Befund 2 zu U16.

2. **Export-Zuständigkeit (UI-002):** U04 liest weiterhin nur `export.catalog`
   und baut Menüs. Eigene `catalog.*`-Handler und direkte Bulk-/Report-/Sitemap-
   Aufrufe entfallen. Die IDs heißen `export.bulk.<name>`, `export.report.<name>`
   und `export.sitemap.<kind>`; Aktivierung folgt `state.available` und den
   Katalogvoraussetzungen. Gruppen-IDs entsprechen U16
   (`export-group-bulk-*`, `export-group-reports-*`), sodass das bestehende
   F04-Ersetzungsverhalten auch zusammengeführte Beiträge dedupliziert.
   Tests: spätere U16-Registrierung/Abmeldung aktiviert/deaktiviert den Eintrag,
   Aktion erreicht ausschließlich den registrierten Export-Controller; kein
   Pfaddialog und kein direkter Exportaufruf. `main.test.ts` baut zusätzlich die
   U04- und U16-Beitragsstruktur in beiden Registrierungsfolgen ohne Duplikate.

3. **Native Accelerators und Gründe (UI-002/UI-113):** Wahl **(a)** aus dem
   Review: U04 nutzt F04s Registermechanismus, nur Bearbeitungskürzel bleiben
   ausgenommen. Kein `nativeAccelerator: false`, kein Kürzel-/Grundsuffix für
   U04-Einträge. Fokuswechsel und Modalzustand bauen das Menü neu auf und
   deaktivieren unzulässige Aktionen entsprechend dem Dispatcher-Scope.
   Ein optionaler, fenstergebundener Action-Guard prüft native Rückrufe nochmals
   synchron gegen den aktuellen DOM-Kontext; auch bereits eingereihte native
   Rückrufe können dadurch keine globale Aktion in einem Dialog auslösen.
   Deaktivierungsgründe sind über die aufklappbare Statuszeile nach Aktionsname
   zugänglich, einschließlich spezifischer Feld-/Dialoggründe. Tauri bietet
   keinen Hover-Callback für native Einträge, deshalb diese Statuszeilenlösung.
   Tests: Register/Accelerators auf mac/win und de/en, Bearbeitungsausnahmen,
   echte Adapter-Erzeugung gegen gemockte native Menü-APIs mit kurzer Beschriftung,
   Fokus-/Modalwechsel einschließlich synchronem Callback-Guard und reaktive
   Statuszeile. Vier **eigene** Menüsnapshots ändern nur den M3-Updategrund.

4. **Spec-Tags/C9:** In `core.spec.ts` und `debug.spec.ts` steht jeweils eine
   kombinierte Tagzeile für `OUT-241 [P1], OUT-244 [P1], OUT-227 [M2]`.
   Der vollständige echte Bridge-Test behält den zulässigen C9-Platzhalter
   `wartet auf M2-O01`: der Command ist hier noch ein Unsupported-Stub.
   N01 entfernt ausschließlich diesen Platzhalter nach Integration von O01.
   Nachweis: eigener Playwright-Lauf und statische Prüfungen. Der eigene
   Sprachwechseltest wartet nun auf die gerenderte App und schaltet über
   `usePrefs.patch` um: Ein erster Gesamtlauf zeigte auf WebKit ein Rennen
   zwischen direktem `setLanguage` und dem verspäteten Laden der Einstellungen.
   Die Erwartungen bleiben unverändert; der gezielte Menü-Nachlauf ist grün.

5. **Benutzerhandbuch (UI-002):** Tauri verwendet den additiven nativen
   App-Command `open_manual`; er öffnet ausschließlich die feste eigene Doku-URL.
   Keine frei übergebbare URL, keine Shell-Prozesse, keine neue Abhängigkeit.
   Umsetzung über NSWorkspace (macOS, auf dem Hauptthread), ShellExecuteW
   (Windows) bzw. GIO (Linux); Fehler werden an den Client zurückgegeben.
   `window.open` bleibt nur im Browser. Test: Help-Aktion verwendet bei
   Tauri-Transport den nativen Command und ruft `window.open` nicht auf.
   Der macOS-Code wird durch die vollständigen Workspace-Prüfungen mitgebaut.
   Produktfrage bleibt die kanonische öffentliche Handbuch-URL; bis dahin das
   eigene Repository-Verzeichnis `docs` wie im ursprünglichen Review akzeptiert.

6. **Bericht:** Dieser Markdown-Bericht unter `docs/plan/M2-reports/u04.md`
   ersetzt `apps/desktop/src/features/help/M2-U04-report.txt`. Der ausdrücklich

## Empfehlungen und Integration (N01)

- **Modusquelle mit U03 zusammenführen:** U03s `useHeader.mode` in
  `features/header/model.ts` wird bei N01 die gemeinsame Quelle für Menü und
  Kopfleiste. Menüauswahl muss dann denselben Moduswechselpfad samt U03-Rückfrage
  bei laufendem Crawl benutzen; Session-/Konfigurationsinitialisierung darf eine
  inzwischen getroffene Auswahl nicht überschreiben. Hier ist U03 noch nicht
  integriert; `useMainMode` bleibt bis N01 lokal und ist entsprechend kommentiert.
  Unbekannte SERP/APIs/Vergleich-Werte werden weiterhin nicht an CrawlConfig gesendet.
- **Abstimmung U16:** IDs und Gruppenstruktur wurden gegen dessen vorhandenen
  Paketbranch geprüft. ExportDialog/ExportHost bleiben alleiniger Besitzer von
  Optionen, nativen Datei-/Verzeichnisdialogen, Fortschritt, Abbruch und
  „Ordner öffnen“. N01 löst die Menübeiträge zu einem Katalogbesitzer auf und
  prüft dabei erneut den Laufstatus von ExportHost; die IDs deduplizieren schon
  vor dieser Bereinigung. Keine Änderungen an fremdem Exportcode.
- **Updates:** `help.updates` bleibt ausdrücklich bis M3/OUT-250 deaktiviert,
  auch wenn später ein Handler registriert wird. Grund: „Verfügbar ab M3.“ / „Available from M3.“
- **CI-Hinweis:** `ui-e2e` führt Playwright aus. Vitest einschließlich
  Menü-Snapshots, `help.test.tsx` und `nativeMenu.test.ts` ist hier lokal belegt.
  Kein Push/PR, daher keine neue CI-Lauf-ID. Browserplattformen simulieren mac/win;
  native Menü-/Dialogbedienung und das Starten eines echten externen Browsers
  sind kein Bestandteil des Browsernachweises. Windows-/Linux-Nativpfade wurden
  auf dem macOS-Host nicht ausgeführt.

+//! Fixed documentation destination, opened by native APIs without spawning a shell.
+use tauri::{AppHandle, Runtime};
+
+const MANUAL_URL: &std::ffi::CStr = c"https://github.com/domdewom2/openspider/tree/main/docs";
+
+#[tauri::command]
+pub async fn open_manual<R: Runtime>(app: AppHandle<R>) -> Result<(), String> {
+    let (tx, rx) = tokio::sync::oneshot::channel();
+    app.run_on_main_thread(move || {
+        let _ = tx.send(open());
+    })
+    .map_err(|e| e.to_string())?;
+    rx.await.map_err(|e| e.to_string())?
+}
+
+#[cfg(target_os = "macos")]
+fn open() -> Result<(), String> {
+    use std::ffi::{c_char, c_void};
+    type Obj = *mut c_void;
+    #[link(name = "objc")]
+    unsafe extern "C" {
+        fn objc_getClass(name: *const c_char) -> Obj;
+        fn sel_registerName(name: *const c_char) -> Obj;
+        fn objc_msgSend();
+    }
+    #[link(name = "AppKit", kind = "framework")]
+    unsafe extern "C" {}
+    // SAFETY: documented NSWorkspace/NSURL signatures, fixed ASCII URL, main thread;
+    // temporary Objective-C objects are scoped to the autorelease pool.
+    let opened = unsafe {
+        let send0: unsafe extern "C" fn(Obj, Obj) -> Obj =
+            std::mem::transmute(objc_msgSend as *const ());
+        let send1: unsafe extern "C" fn(Obj, Obj, Obj) -> Obj =
+            std::mem::transmute(objc_msgSend as *const ());
+        let string: unsafe extern "C" fn(Obj, Obj, *const c_char) -> Obj =
+            std::mem::transmute(objc_msgSend as *const ());
+        let open_url: unsafe extern "C" fn(Obj, Obj, Obj) -> bool =
+            std::mem::transmute(objc_msgSend as *const ());
+        let pool = send0(
+            objc_getClass(c"NSAutoreleasePool".as_ptr()),
+            sel_registerName(c"new".as_ptr()),
+        );
+        let text = string(
+            objc_getClass(c"NSString".as_ptr()),
+            sel_registerName(c"stringWithUTF8String:".as_ptr()),
+            MANUAL_URL.as_ptr(),
+        );
+        let url = send1(
+            objc_getClass(c"NSURL".as_ptr()),
+            sel_registerName(c"URLWithString:".as_ptr()),
+            text,
+        );
+        let workspace = send0(
+            objc_getClass(c"NSWorkspace".as_ptr()),
+            sel_registerName(c"sharedWorkspace".as_ptr()),
+        );
+        let opened =
+            !url.is_null() && open_url(workspace, sel_registerName(c"openURL:".as_ptr()), url);
+        send0(pool, sel_registerName(c"drain".as_ptr()));
+        opened
+    };
+    if opened {
+        Ok(())
+    } else {
+        Err("Could not open documentation URL".into())
+    }
+}
+

+fn open() -> Result<(), String> {
+    use std::{ffi::c_void, ptr};
+    #[link(name = "shell32")]
+    unsafe extern "system" {
+        fn ShellExecuteW(
+            window: *mut c_void,
+            verb: *const u16,
+            file: *const u16,
+            args: *const u16,
+            dir: *const u16,
+            show: i32,
+        ) -> isize;
+    }

+        .to_string_lossy()
+        .encode_utf16()
+        .chain(Some(0))
+        .collect();

+    let result = unsafe {

+            ptr::null_mut(),
+            ptr::null(),
+            url.as_ptr(),
+            ptr::null(),
+            ptr::null(),

+    } else {

+    }
+}
