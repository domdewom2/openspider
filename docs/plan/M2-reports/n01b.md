## 5. ui-e2e-b (nächtlicher native-smoke)

- **Windows:** „session not created: DevToolsActivePort file doesn't exist“. Belegt über msedgedriver-Protokoll und eine Probe: msedgedriver übergibt `--remote-debugging-port=0` per `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`; die WebView2-Kommandozeile der App enthält nur die Standardargumente von wry (`--disable-features=…`), weil wry die zusätzlichen Argumente über die API setzt – Umgebungsvariable und auch ein WebView2-Richtlinien-Registrywert greifen nicht. WebViews eines Datenordners müssen gleiche Argumente haben, daher bekommt im **Testbuild** (nur im Workflow, `TAURI_CONFIG`; Produktkonfiguration unverändert) auch das Einstellungsfenster `additionalBrowserArgs`, wird von Anfang an (versteckt, `url: settings.html`) erzeugt und per Label gefunden.
- Weitere Änderungen am Prüfaufbau: `run.mjs` startet unter Windows `msedgedriver` selbst (`--verbose`, Protokoll `msedgedriver-<n>.log` im Artefakt) mit den Capabilities von tauri-driver (`browserName: webview2`, `ms:edgeOptions.binary`) und wiederholt die Sitzung einmal; `cargo install tauri-driver` entfällt im Workflow (~6 min), `S02_WINDOWS_DRIVER=tauri` bleibt wählbar; Diagnose-Probe (Kommandozeilen, Debug-Port) bei Sitzungsfehler; `workflow_dispatch` erhält die Eingaben `platforms`/`mode`.
- Ergebnis: Lauf **39654811661** (Windows) und **39651193074** (macOS) – smoke grün.
