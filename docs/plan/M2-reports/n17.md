## Ursachen und Änderungen

### N17-01: fehlender Fixture-Server auf allen Plattformen

Lauf `41158683045`, Logs `e2e-124411094747.log` (Linux-WebKit), `e2e-124411094963.log`
(Windows-Chromium) und `e2e-124411094967.log` (macOS-WebKit) wurden ausschließlich als Daten gelesen.
Elf Tests je Plattform scheitern beim Start von `os-testsite` mit `ENOENT`, bevor der eigentliche Test beginnt.
`.github/workflows/ui-e2e.yml` baute nur die Bridge. Die Beta-Fixtures verwenden `alpha/support.ts`
(`startSite`, `toolBinary`), `beta/n04-live.spec.ts` startet den Server direkt, `mcp/realBridge.ts` ebenso.

Der Workflow baut vor Playwright zusätzlich `os-testsite`, `os-cli` (Binary `openspider`) und `os-parity`
mit `cargo build --locked -p os-testsite -p os-cli -p os-parity --bins`.
Die beiden weiteren Werkzeuge sind aus `alpha/fixture.ts`/`alpha/support.ts::ensureTools`,
`alpha/foreign-crawl.spec.ts`, `alpha/mcp.ts` und `alpha/export.spec.ts` abgeleitet:
Die Gesamtsuite benötigt CLI und Paritätsvergleich und darf sie nicht erst während paralleler Tests bauen.
Cargo erzeugt auf Windows `.exe`; `alpha/support.ts::toolBinary`, `support/bridge.ts::bridgeBinary`
und `mcp/realBridge.ts` berücksichtigen die Endung bereits. Keine hartkodierten ausführbaren Pfade ergänzt.

### N17-02: native macOS-WebKit-Tastaturnavigation (UI-126)

Linux-WebKit: 476 bestanden, elf ausschließlich wegen N17-01 fehlgeschlagen, drei bereits vorhandene Skips,
zwei abhängige Performance-Tests nicht ausgeführt. Alle hier untersuchten a11y-Tests waren dort grün.
macOS-WebKit: dieselben elf Serverfehler plus sieben a11y-Fehler:

| Test | Tatsächlicher Fehler im Log | Einordnung |
| --- | --- | --- |
| `a11y/contrast.spec.ts:62`, forced-colors/more × light/dark | `tabTo` erreicht den nativen Button „Green“ nicht (`:85`) | Vier Fokusfehler; keine fehlgeschlagene Kontrast-, Checkbox-, Switch- oder Radio-Erwartung |
| `a11y/grid.spec.ts:4` | Schon der native Button „Before grid“ wird nach dem ersten Tab nicht fokussiert (`:9`) | Isolierte Grid-Fixture, vor Prüfung von Scrollen/absoluten Indizes; unabhängig von UpperTable |
| `a11y/keyboard.spec.ts:129` | Inventar lässt native Buttons wie „All (3)“, „HTML (3)“, Overview-Aktionen aus | Entspricht derselben nativen Fokusregel |
| `a11y/keyboard.spec.ts:137` | Ein sequenzieller Settings-Control fehlt im Inventar | Entspricht derselben nativen Fokusregel; native Bestätigung bleibt erforderlich |

WebKit übernimmt unter macOS die Systemeinstellung „Keyboard navigation“. Native Buttons ohne explizites
`tabindex` können dadurch bei Tab übersprungen werden, während explizite Tabstopps erreichbar bleiben.
Der passende [Playwright-Befund #41808](https://github.com/microsoft/playwright/issues/41808)
beschreibt genau dieses Verhalten; ein Playwright-Maintainer bestätigt die beabsichtigte Safari-Parität.
Der dort dokumentierte prozessbezogene Schalter ist `defaults write org.webkit.Playwright AppleKeyboardUIMode -int 2`.
Der Workflow setzt ihn ausschließlich auf dem kurzlebigen macOS-Runner vor dem Browserstart.

Unter Linux-WebKit lässt sich die macOS-Cocoa-Systempräferenz nicht nachstellen. Die identischen isolierten
Tests prüfen dort weiterhin echte Tab-Ereignisse, native Buttons, forced-colors/more und Zustandsmerkmale.
Die native Wirksamkeit des Schalters und das vollständige Settings-Inventar müssen im Testzweig bestätigt werden.
Es gibt anhand dieser Logs keinen belegten Produktfehler in den N12-Änderungen an UpperTable/ARIA/Kontrasten.

K2-63: alte und neue Testerwartungen sind identisch (UI-126); keine Schwelle, Testlogik, Skip-/Fail-Markierung
oder Golden geändert. Die Plattformvorbedingung wird explizit in der CI-Testkonfiguration hergestellt.
K2-92: keine Produktdatei unter `apps/desktop/src/**` geändert; keine Fremdänderung erforderlich.
Keine neuen Zurückstellungen, Spec-Unklarheiten oder Schnittstellenbedarfe.

## Nativer Prüflauf durch den Orchestrator

Nach Integration von N13 auf `m2/int-19` einen Testzweig mit N17 erstellen und pushen.
Der Push auf `m2/**` startet `ui-e2e` bereits; alternativ manuell (keinen Doppelstart auslösen):

```sh
gh workflow run ui-e2e.yml --ref <testzweig>
gh run list --workflow ui-e2e.yml --branch <testzweig> --limit 3
gh run watch <run-id> --exit-status
```

Die vollständige Matrix muss macOS-WebKit, Windows-Chromium und beide Linux-Engines bestätigen.
Besonders die sieben oben aufgeschlüsselten macOS-a11y-Fälle und die elf Serverfälle je Plattform prüfen.
Native Lauf-ID und Resultat trägt der Orchestrator hier nach. Dieser Linux-Bericht behauptet keine grüne native CI.
