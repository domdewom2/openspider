## Umgesetzte Spec-IDs

- **CRAWL-055, ONPAGE-170 [M2]:** img-/picture-srcset erzeugt bei aktivierter Option Image-Links für alle Kandidaten (inklusive w-/x-Deskriptoren und Komma in der URL). Instanzen bleiben auch ohne Option erhalten; ein Loopback-Crawl prüft URL-Mengen, gespeicherte Instanzen und tatsächlich empfangene Requests.
- **ONPAGE-172:** Auswahl nach einbindender Seite oder Bild-URL, eindeutige Vereinigung bei Mehrfachauswahl, Gesamtzahl, Paging und Sortierung. Paritätsspalten in Spec-Reihenfolge; `Source` und `Alt Text Length` nur mit `extensions=true`. Reale/angezeigte Maße nur bei Viewport-Rendering; SVG ohne reale Rastermaße. Optional liest der Antwort-Hook PNG/JPEG/GIF/WebP/AVIF-Dateiköpfe, auch für externe Ressourcen (`image.real_w`, `image.real_h` in `url_ext`). AVIF berücksichtigt die Eigenschaftszuordnung des primären Items. XPath, Linkposition, Pfadart und Herkunft bleiben je Instanz erhalten.
- **ONPAGE-178:** optionale Instanzen aus style-Attributen und style-Blöcken über den bestehenden CSS-Parser. Die Crawl-Analyse klassifiziert CSS-/dynamische Bilder global und schließt jede URL mit img-/srcset-Instanz auf einer beliebigen Seite aus. Atomare, wiederholbare Ersetzung; Änderungen stempeln den Änderungsfeed, Abbruch behält den vorherigen Stand.
- **ONPAGE-179:** fehlende oder leere width-/height-Attribute auf Instanzebene; CSS-Größen ersetzen keine HTML-Attribute.
- **ONPAGE-180:** Einsparung aus Größen-/Flächenverhältnis, Schwellwert inklusive Gleichheit, keine Einsparung für hochskalierte, unsichtbare, nicht im Viewport gerenderte Bilder oder SVG. Die Schätzung wird als ganzzahlige Bytezahl ausgegeben; die konfigurierte Schwelle 0 wird ebenfalls unterstützt.
- **ONPAGE-181, OUT-053:** acht Bildexporte, exakt zwölf Instanzspalten, CSV und XLSX, passende Instanzen statt sämtlicher Einbindungen einer problematischen Bild-URL. Strikte Alt-/Byte-Grenzen; numerische sowie X-Exportnamen; Spec-Schreibweise `Background Images` als Alias der bestehenden Kennung `Background Images Inlinks`. Ein SQL-Lauf streamt den Export ohne Detail-Paging-Grenze und ohne vollständige Ergebnisliste im Rust-Speicher. Fehlende Analyse-/Rendering-Voraussetzungen liefern eine Kopfzeile ohne Daten und einen konkreten `tracing::warn!`-Hinweis auf den Filterzustand (OUT-112). Background/Incorrectly Sized behalten zusätzlich `ReportRequirement::Rendering` für die vorhandene Warnmechanik in `ExportFileInfo.warnings`. Eine `RenderingOrConfig`-Variante existiert im Report-Katalog noch nicht; bei aktivierter Inline-CSS-Option funktioniert der Background-Export trotzdem, der statische Rendering-Hinweis bleibt gemäß Review bestehen.
- Drei neue Image-Issues mit eigenen deutschen/englischen what/why/fix-Texten und Dokumentation.

## Erwartungsänderungen (K2-63)

Datei: `crates/os-mcp/tests/tools_read.rs`, Test `issues_that_need_the_crawl_analysis_are_named_instead_of_counted` (`AGENT-013`). Ausschließlich die bestehende Assertion wird für die eigenen drei Filter `Images:Background Images`, `Images:Missing Size Attributes` und `Images:Incorrectly Sized Images` auf `needs_rendering` präzisiert. Alle übrigen Einträge müssen weiterhin `needs_crawl_analysis` liefern; Produktivcode und Testaufbau bleiben unverändert.

Begründung: ONPAGE-007 unterscheidet fehlende Voraussetzungen ausdrücklich. ONPAGE-178/180 verlangen ohne Rendering `needs_rendering`; für ONPAGE-179 schreibt die eingefrorene Registry/Paketvorgabe denselben Zustand vor (separater Klärungsbedarf unten). Die bisherige pauschale Erwartung widerspricht damit zwingend dem D03-Vertrag. K2-63 ist durch den aktuellen Nutzerauftrag und die Review-Entscheidung ausdrücklich freigegeben.

```diff
-    assert!(pending.iter().all(|p| p["state"] == "needs_crawl_analysis"));
+    assert!(pending.iter().all(|p| {
+        let own_image_filter = p["tab"] == "Images"
+            && matches!(p["filter"].as_str(),
+                Some("Background Images" | "Missing Size Attributes" | "Incorrectly Sized Images"));
+        p["state"] == if own_image_filter { "needs_rendering" } else { "needs_crawl_analysis" }
+    }));
```

**Merge-Hinweis für den Integrator:** M2-D02 ändert dieselbe Assertion für `Content:Near Duplicates` auf `needs_config`. Beim Merge beide spezifischen Zweige zusammenführen, dann erst auf `needs_crawl_analysis` zurückfallen. D03 nimmt die noch nicht vorhandene D02-Fachlogik nicht vorweg.

## Abweichungen und offene Fragen

**ONPAGE-179 / eingefrorener F05-Vertrag:** Die Fach-Spec beschreibt Missing Size Attributes ohne Voraussetzung. `M2-filters.toml`, `tabs::M2_FILTERS` und Paketvorgabe 3.14 ordnen den Filter dagegen `post_crawl:Images` mit `RenderingOrConfig(images.parse_inline_css_backgrounds)` zu. Diese vorhandene Zustandssemantik bleibt erhalten; ohne Rendering/Inline-CSS liefert der Filter `NeedsRendering`. Die Attributprüfung selbst benötigt kein Rendering. Der offene [K2-Klärungseintrag für Planer/N01](../../../tests/fixtures/onpage-m2-images/K2-clarifications.md) fordert eine Entscheidung über die spätere koordinierte Freigabe als Live-Filter; dieses Paket verändert weder die eingefrorene Registry noch fremde Vertragstests dafür.

Die echte Browser-Erfassung (Viewport, externe Stylesheets, JS/Lazy Loading und Origin-Zusammenführung) liegt gemäß Paketaufteilung bei M2-R01/E05/R02. Hier werden vollständige persistierte Rendering-Fakten aus dem F05-Vertrag geprüft. Der vorhandene M1-Lazy-Load-Ignore verbleibt ausschließlich für M2-R02; der srcset-Teil ist aktiv getestet. D16 liefert später die benutzerdefinierten Positionsregeln; D03 ruft den vorhandenen Klassifikations-Erweiterungspunkt auf.

Numerische Namen stehen über den dynamischen Katalog bereit; die bestehenden X-Namen bleiben als stabile Einträge/CLI-Schreibweisen erhalten.
