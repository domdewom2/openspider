## Fremdänderung (K2-75a)

Keine Fremddatei geändert. Für A02-07/A02-08 liegt der fehlerhafte Query-Hook in
`apps/desktop/src/features/sidebar/frame/useSidebarQuery.ts`, außerhalb von N03
(`sidebar/{overview,issues,analysis}`) und innerhalb des parallelen U34-Besitzes
(`sidebar/frame/**`). Ein Fix ausschließlich in `Overview.tsx` kann das nicht lösen:
Die Komponente wird vom Frame ohne Query-Daten gar nicht gerendert.

Erforderlicher Lösungsrahmen: Query-Identität an Crawl/Scope binden, Versionswechsel
als gebündelte Invalidierung behandeln und vorherige erfolgreiche Daten während
neuer Anfragen anzeigen; laufende Requests nicht bei jedem Tick verdrängen. Bei
Crawl-/Scope-Wechsel dürfen keine alten fremden Daten sichtbar bleiben.

Die Paketregel „nur Dateien aus owns ändern, sonst abbrechen und melden“ und der
explizite Auftrag, U34-Dateien nicht anzufassen, verhindern diesen Eingriff.
Keine Änderung an os-store/os-engine, Grid, primitives, CSS, Manifesten oder Lockfile.
Tokio bleibt unverändert; kein `cargo update`.

## Erforderliche Fremdänderung: konkreter Ansatz

Datei: `apps/desktop/src/features/sidebar/frame/useSidebarQuery.ts:13`.
Unangewandter Diff-Auszug für den Planer/Integrator (kein vollständiger Fix):

```diff
-  return useQuery({ queryKey: ["sidebar", "overview", crawl, scope, counts, version], queryFn: ({ signal }) => sidebar.overview(scope, signal), enabled: !!crawl, gcTime: 0 });
+  // Query-Identität nur für Crawl und Scope; Versionsereignisse werden separat
+  // in einer seriellen, nachlaufenden Invalidierung zusammengefasst.
+  const query = useQuery({ queryKey: ["sidebar", "overview", crawl, scope], queryFn: ({ signal }) => sidebar.overview(scope, signal), enabled: !!crawl, gcTime: 0 });
```

Die dazugehörige Invalidierung muss während einer Anfrage eintreffende Versionen
vormerken und nach Abschluss höchstens alle 500 ms nachladen. Erfolgreiche Daten
bleiben währenddessen sichtbar. Einfach nur `placeholderData` einzusetzen behebt
das Verdrängen von Antworten bei fortlaufendem Versionswechsel nicht. Der Frame
gehört U34; dessen Dateien wurden weder geändert noch zurückgesetzt. Kein
Umweg über globale Query-Defaults, keinen Datenbank-/Writer-Eingriff und keinen
Seiteneffekt beim Import einer N03-Komponente eingebaut.
