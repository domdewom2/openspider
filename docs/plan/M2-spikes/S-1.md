# M2-S01 – S-1 Grid-Gate

Stand: 18.10.2026. Clean-Room: ausschließlich Spec, Plan und eigener Code; kein Zugriff auf das Referenzprodukt.

## Ergebnis und Gate-Empfehlung

**G0 noch nicht freigeben.** Glide `6.0.4-alpha24` ist installierbar, aber sein ARIA-Baum fehlt unter React 19 StrictMode in Chromium und WebKit. Der Kontrolllauf ohne StrictMode sowie die gebaute native App liefern `aria-rowcount=5000001`. Ursache im installierten MIT-Paket: `useDebouncedMemo` setzt `mountedRef` im Effect-Cleanup auf `false`, setzt es beim StrictMode-Remount jedoch nicht zurück. Deshalb wird der zunächst bei Breite 0 leere Accessibility-Baum nicht nachgeführt. Das ist ein reproduzierbarer Kandidatenbefund, kein fehlgeschlagener Adapter-Unit-Test.

Nach M2.md 3.9 führt ein verfehltes Kriterium (5) zu **Fallback B / M2-U02B**. Empfehlung: diesen Befund in G0 entscheiden; nicht allein aufgrund bestandener Scroll-Tests Stufe 0 freigeben. Eine gezielte Bibliothekskorrektur wäre technisch kleiner, wird hier aber nicht umgesetzt: `prompt_notes` erlauben Fallback 0 in S01 nur bei nicht installierbarem npm-Paket. Kein Vendoring, kein Fallback A/B implementiert.

## Gelieferter Produktcode

- `src/data/ViewDataSource.ts`: IPC über die bestehenden `view.*`-Wrapper, synchrone Loading-Zellen, 200 Zeilen pro Block, maximal 100 Blöcke / 20.000 Zeilen, Deduplizierung, zwei Bildschirmseiten Puffer, sichtbare Blöcke zuerst, Abbruch und Generationsprüfung, Anker per `locate`, Tail nur unsortiert am Ende, Freigabe beim Schließen. Keine React-Abhängigkeit.
- `src/state/selection.ts`: unveränderliche URL-ID-Auswahl, Umschalten und Bereiche, Fokus/Anker, „alle außer“ als versionsgebundene Auswahl ohne Materialisierung von fünf Millionen Zeilen. Membership wird über ein Set geprüft.
- `src/grid/DataGrid.tsx`: schmale öffentliche Schnittstelle ohne Glide-Typen; Row als Datenspalte, Row/Address standardmäßig angeheftet, kontrollierte Spaltenbreite/-reihenfolge, Sortier-/Kontext-/Aktivierungs-Hooks, Tastaturauswahl, Zeilenfarben und typisierte Zellen. Der Besitzer der Tab-Oberfläche persistiert `ColumnState` über `onColumnsChange`; der Adapter besitzt keine zweite Persistenz.
- `src/grid/cells.ts`: de/en-Zahlen, Sekunden mit drei Nachkommastellen, Datum, Boolean, URL, Statusfarben plus Text, Rohbytes mit KB/MB-Tooltip, leere Nullwerte, Tooltip-Grenze 2.000 Zeichen. Theme aus den bestehenden Tokens.
- `src/grid/copy.ts`: ausschließlich `view.copy`, sichtbare Spalten in Anzeigereihenfolge, Bestätigung ab 100.001 Zeilen, Export-Hook oberhalb einer Million Zellen. Glide-Kopieren, Cut, Paste und Editieren sind deaktiviert. Kontextmenüs/Bestätigungsdialoge werden durch die aufrufende Oberfläche bereitgestellt.
- `os-app::stub`: Feature **und** Laufzeit-Opt-in; pro App/Fenster isolierte synthetische View, 5.000.000 × 65, begrenzte Fenster, stabile IDs, Versionen, Row-Sortierung in beide Richtungen, `locate`, `close`, TSV-Kopieren über `DesktopActions`, Bereinigung beim Fensterschließen. Unterstützte Fixture-Spec: `Internal/All` ohne Suche/Segment/Vergleich; andere Specs liefern ausdrücklich `Unsupported`.
- Recorder und getrennte Playwright-Konfiguration unter `e2e/grid/`; `.gate.ts` wird von der normalen E2E-Suite ohne `stub-views` nicht versehentlich gestartet. Die Recorder-Seite gehört ausschließlich zum separaten Spike-Build.

Die Spec-IDs **UI-007, UI-012, UI-140** sind in Fixture-, Logik-, Adapter-, Rust- und Browsertests referenziert. UI-007/UI-012 werden hier im Adapter-/Kopiervertrag umgesetzt; Tab-Persistenz und die konkrete Kontextmenü-Oberfläche bleiben Integration der späteren UI-Pakete. UI-140 ist wegen des Gate-Befunds und ausstehender verbindlicher Plattformmessungen **nicht als abgenommen** zu verstehen.

## Messverfahren

Lokale Maschine: Apple M1, 16 GiB RAM, macOS 26.3 (25D125). Sie weicht von UI-Referenz A (MacBook Air M1, **8 GiB**) ab. Browser und native App werden ausdrücklich getrennt ausgewiesen. Performancewerte sind Indizien, keine verbindliche Abnahme auf Referenz A. Normale Workspace-Prüfungen können gleichzeitig laufen; maßgebliche Messblöcke sind vom Orchestrator auf ruhiger Referenzhardware zu wiederholen.

Automatisches Scrollen erfolgt über das echte Scroll-Element. Ein manueller Trackpad-/Mausrad-Lauf und VoiceOver/NVDA bleiben zusätzliche Abnahmeschritte.

Messdateien: `apps/desktop/dist/grid-results/**/S-1-*.json` und `results.json`; native Werte unter dem gewählten Ausgabeordner als `report.json`, Screenshots und `native.log`. CI lädt sie als Artefakte hoch. Die Tests prüfen den Recorder und die Produktverträge; die `checks` in den Artefakten dokumentieren Gate-Verletzungen ausdrücklich, ohne weitere Rasterpunkte zu überspringen.

## Reproduktion

Vom Repository-Hauptverzeichnis:

```sh
npm ci
cargo build -p os-app --locked --features e2e-bridge,stub-views --bin os-app-bridge
npm run -w apps/desktop e2e -- --config e2e/grid/playwright.config.ts --project=chromium --project=webkit
npm run -w apps/desktop tauri -- build --debug --no-bundle --features stub-views,e2e-webdriver --config e2e/grid/native.conf.json
node apps/desktop/e2e/grid/native.mjs target/debug/openspider-desktop target/loadtest/grid-native
```

Bei abweichendem `CARGO_TARGET_DIR` den tatsächlichen Binary-Pfad übergeben; unter Windows `.exe`. `native.mjs` setzt temporäres `OPENSPIDER_HOME`, Memory-Secrets, `OPENSPIDER_STUB_VIEWS=1` und einen ephemeren WebDriver-Port. Keine Benutzereinstellungen werden überschrieben. Native Messungen fokussieren das Messfenster. Für interaktive Messung:

```sh
OPENSPIDER_SECRET_STORE=memory OPENSPIDER_STUB_VIEWS=1 npm run -w apps/desktop tauri -- dev --features stub-views --config e2e/grid/native.conf.json
```

Recorder: „Last row“, vertikal/horizontal je zehn Sekunden, Zoomwahl. Bei VoiceOver den Grid-Baum und die Ansage von 5.000.001 Zeilen prüfen; ein DOM-Attribut allein ersetzt diese Prüfung nicht. `?strict=0` ist ausschließlich ein Diagnosevergleich und kein Workaround für die Produkt-App.
