# S-6 – Sichtbarkeitsdrosselung: statischer Vorbefund

Stand: 2026-10-17, macOS 26.3, Ausgangsstand `e6149ee`.
Status: **nicht gemessen**; M2-S02 wurde beim Schnittstellenbedarf S-5b
abgebrochen (siehe [S-5b](S-5b.md)).

## Befehle und Ergebnis der Quellprüfung

```sh
rg -n 'visibility|Occlusion|is_minimized' apps/desktop/src-tauri/src/window.rs
rg -n 'frontend|shell|is_visible' crates/os-app/src/runtime/windows.rs
```

`window.rs` meldet bei Focus-/Resize-/Move-Ereignissen nur
`is_visible() && !is_minimized()` an `App::set_visibility`. Der Modulkommentar
bestätigt ausdrücklich, dass der native macOS-Occlusion-Zustand nicht erfasst
wird. `runtime/windows.rs` verknüpft Frontend- und Shell-Sichtbarkeit mit UND;
diese Verknüpfung ist vorhanden, die zusätzliche native Occlusion-Quelle aus
M2-ui-concept 2.5 fehlt.

Das ist ein statischer Befund, kein Beweis für eine Überschreitung von 1 Hz.
Insbesondere ist ein nicht fokussiertes Fenster nicht automatisch verdeckt.
Die tatsächliche Tickfrequenz bleibt offen.

## Entscheidungsvorschlag und Schnittstellenbedarf

Vor einer Freigabe von UI-143 die echte App bei laufendem Fixture-Crawl auf
macOS beobachten: sichtbar, minimiert, wiederhergestellt, vollständig durch
ein anderes Fenster verdeckt und wieder freigelegt. Beide Sichtbarkeitsquellen
sowie Tick-Zeitstempel getrennt protokollieren; nach Übergangsphase mindestens
30 Sekunden je Zustand messen, unsichtbar höchstens 1 Hz, danach Rückkehr zur
konfigurierten sichtbaren Frequenz prüfen. Frontend-Signale allein belegen die
native Quelle nicht.

Für die vollständige Implementierung der geplanten nativen Quelle wäre eine
Änderung in `apps/desktop/src-tauri/src/window.rs` erforderlich (außerhalb
`owns`). Konzeptioneller Diff-Ausschnitt, **nicht angewendet**:

```diff
-    let visible = window.is_visible().unwrap_or(true) && !window.is_minimized().unwrap_or(false);
+    // macOS: zusätzlich nativen NSWindow-Occlusion-Zustand einbeziehen
+    // und dessen Änderungen unabhängig von Focus/Resize/Move abonnieren.
```

Die konkrete native API-/Lebensdauer-Integration muss das zuständige
Hüllenpaket ausarbeiten; dieser Ausschnitt ist kein kompilierbarer Patch.
Keine Änderung an fremdem Code und keine Freigabe oder Ersatzmessung durch
einen simulierten Sichtbarkeitsaufruf.
