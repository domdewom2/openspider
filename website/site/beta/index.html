OpenSpider · Beta

OpenSpider 1.0 testen

Die Beta von OpenSpider 1.0 ist offen: für SEO-Freelancer, Inhouse-Teams und Agenturen. Sie ist kostenlos, der Quellcode steht unter der Apache-2.0-Lizenz auf GitHub. Probiere den Crawler an deinen eigenen Websites aus und sag uns, was funktioniert und was nicht.

Installer auf GitHub ↗Rückmeldung geben

Herunterladen und installieren

Alle Installer liegen auf der Release-Seite auf GitHub ↗. Die neueste Version steht oben. Unter „Assets“ wählst du die Datei für dein System:

  • macOS 13 oder neuer: das Universal-DMG (Dateiname endet auf _universal.dmg), läuft auf Apple Silicon und Intel. DMG öffnen und OpenSpider in den Ordner „Programme“ ziehen.
  • Windows 10 (ab 1809) oder 11, x64: die Setup-EXE (_x64-setup.exe) installiert für dein Benutzerkonto ohne Administratorrechte. Das MSI-Paket (.msi) installiert für alle Konten des Rechners und braucht Administratorrechte. Windows on ARM nutzt den x64-Installer unter Emulation.
  • Linux: nur Kern und Kommandozeile als Archiv (_linux-x86_64.tar.gz), keine Desktop-App.

Wie du die Dateien gegen SHA256SUMS prüfst, steht auf der Download-Seite.

Erster Start

macOS: Die App ist signiert und von Apple notarisiert. Beim ersten Öffnen fragt macOS einmal nach, ob du die aus dem Internet geladene App öffnen möchtest. Bestätige das, wenn als Quelle der Download von GitHub angezeigt wird.

Windows: Die Installer sind signiert. Weil das Signaturzertifikat neu ist, kann Microsoft Defender SmartScreen anfangs trotzdem warnen. Dann auf „Weitere Informationen“ klicken, den angezeigten Herausgeber prüfen und „Trotzdem ausführen“ wählen. Mehr dazu im Handbuch.

Bevor du loslegst

Beta-Software: Sichere wichtige Crawls, bevor du die App aktualisierst. Datei → „Crawl speichern unter…“ legt eine Kopie der Crawl-Datei an.

Während der Beta aktualisiert sich OpenSpider über die eingebaute Update-Funktion: Die App prüft beim Start höchstens einmal am Tag auf eine neue Beta und installiert sie erst nach deiner Bestätigung. Manuell geht das über Hilfe → „Nach Updates suchen“. Du musst neue Versionen nicht selbst herunterladen.

Vier Testaufgaben

Diese vier Abläufe helfen uns am meisten. Alles andere darfst du natürlich auch ausprobieren.

  1. Deine eigene Website crawlen, gern eine mit 10.000 URLs oder mehr.
  2. Den laufenden Crawl pausieren und wieder fortsetzen.
  3. Ergebnisse exportieren, zum Beispiel eine Tabelle oder einen Bericht.
  4. Die App beenden, neu starten und den Crawl wieder öffnen (Datei → „Zuletzt geöffnet“).

Technisch versiert? Fehler und Ideen kannst du auch direkt als Issue auf GitHub ↗ melden (öffentlich, also ohne Kundendaten). Beiträge per Pull-Request sind willkommen, siehe CONTRIBUTING.md ↗.

Datenschutz der Beta-Updates

Betas sind bis 1.0 normale GitHub-Releases mit latest.json und latest-beta.json. Es gibt keine Kanalwahl in der Oberfläche. Automatische Prüfungen senden nur Version, Betriebssystem und Architektur, keine Nutzerkennung oder Crawl-Daten und keine Telemetrie. GitHub sieht die für die Verbindung erforderliche IP-Adresse. Unter Einstellungen → Updates oder mit OPENSPIDER_DISABLE_UPDATE_CHECK=1 abschaltbar. CLI und geplante Läufe prüfen nie automatisch. Siehe Update-Verhalten und Datenschutz. Was mit den Angaben im Formular geschieht, steht in der Datenschutzerklärung.
